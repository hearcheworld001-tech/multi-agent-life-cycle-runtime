# Multi-Agent Life Cycle Runtime

面向长期存在智能体的生命运行时设计。

本项目研究的不是“收到请求、调用模型、返回结果”的一次性 Agent 工作流，而是一个能够让多个 Agent 在受控环境中持续存在、感知世界、积累经验、从故障中恢复、与其他 Agent 协作，并在可验证边界内演化的运行时。

> **Engine 提供生命环境，Agent 产生生命行为。**

## 为什么需要生命运行时

短生命周期 Agent 通常可以抽象为：

```text
接收任务 -> 推理 -> 调用工具 -> 返回结果 -> 结束
```

这种模式没有回答长期运行所必需的问题：

1. 重启后如何保留身份、目标和未完成工作的连续性？
2. 外部系统失败、网络中断或工具返回脏数据时，谁负责恢复？
3. 一次成功经验什么时候可以被复用，什么时候只是偶然？
4. 多个 Agent 共享哪些信息，哪些信息必须隔离？
5. Agent 能否修改自己的策略；如果修改失败，如何验证和回滚？
6. 资源、权限、审计和人工接管的边界在哪里？

本项目把这些问题提升为运行时的一等概念，而不是散落在业务代码中的补丁。

## 五项核心能力

1. **持续运行**：管理创建、激活、心跳、休眠、唤醒、迁移、重启和终止，并保持身份连续性。
2. **故障恢复**：区分重试、回滚、任务转移、隔离和 Agent 级恢复，记录原因、动作、结果和恢复点。
3. **自我进化**：让经验经过反思、评估、实验和验证后，才可能更新知识、技能、策略或流程。
4. **环境认知**：通过受控传感器观察用户、服务、数据、资源和其他 Agent，维护可追溯的世界模型。
5. **自我认知**：维护身份、目标、能力、限制、表现、失败模式和成长历史的自我模型。

这五项能力共同构成 Agent 的生命机制，不是额外的插件清单。

## 核心边界

### Agent 是什么

Agent 是具有稳定身份、目标、状态、能力、记忆和行为循环的自主执行实体。它负责目标解释、判断、行动、经验积累和受约束的成长。

### Engine 是什么

Engine/Runtime 是 Agent 的生命基础设施，负责生命周期、调度、心跳、持久化、通信、资源、安全、环境接口、健康检查和故障编排。

Engine 不应悄悄替 Agent 做价值判断，也不应在没有审计记录的情况下修改 Agent 的认知状态。两者的责任边界见[总体概览](docs/guide/overview.md)和[核心契约](docs/guide/contracts.md)。

## 总体模型

```text
外部环境
  用户 / API / 文件 / 数据 / 服务 / 其他 Agent / 定时事件
                              |
                              v
环境接入与感知层
  传感器 -> 观测 -> 理解 -> 世界模型 -> 预测
                              |
                              v
Agent
  身份 | 目标 | 记忆 | 自我模型 | 能力
  决策 | 行动 | 评估 | 反思 | 恢复 | 演化
                              |
                              v
Multi-Agent Life Runtime
  生命周期 | 调度 | 心跳 | 通信 | 持久化
  资源 | 安全 | 恢复 | 休眠/唤醒 | 可观测性
```

Runtime 提供边界、时间、资源和恢复语义；Agent 在这些边界内产生行为。

## 设计原则

- **生命连续性优先**：重启、休眠和迁移不能无声抹去身份、目标和经验。
- **状态显式化**：重要状态、状态转换、恢复点、版本和原因都必须可追踪。
- **边界可验证**：外部环境必须通过受控接口进入；权限和资源不能依赖隐式约定。
- **经验有来源**：记忆、能力和演化结论需要保留来源、时间、评价和适用范围。
- **失败可恢复**：每个可变更动作都应定义幂等性、超时、重试、回滚或隔离策略。
- **演化有门禁**：观察到的改进建议不能直接变成生产行为，必须经过实验、验证和发布。
- **先契约后实现**：先稳定概念、状态机、事件和接口语义，再选择框架、数据库和消息设施。
