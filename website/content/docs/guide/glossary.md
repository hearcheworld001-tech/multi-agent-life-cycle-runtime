# 术语表

本页定义文档中的标准用词。新文档应优先复用这些术语，避免同一概念使用多个近义词。

## 核心实体

| 术语 | 定义 | 容易混淆的概念 |
| --- | --- | --- |
| Agent | 拥有稳定身份、目标、状态、能力、记忆和行为闭环的自主实体 | 不是一次模型调用或单个进程 |
| Agent Instance | Agent 在某个进程或节点上的运行实例 | 实例可以重建，Agent 身份继续存在 |
| Runtime / Engine | 管理 Agent 生命周期、资源、状态、通信、安全和恢复的基础设施 | 不是 Agent 的大脑或目标决策者 |
| Environment | Agent 之外产生观测或承受动作结果的一切 | 不等于 Runtime |
| World Model | Agent 对环境实体、关系、状态、事件和预测的可更新解释 | 不等于客观事实本身 |
| Self Model | Agent 对自身能力、限制、表现和历史的模型 | 不等于模型自述 |
| Capability | 可调用且具有权限、版本和表现证据的能力 | 不只是工具名称 |

## 生命周期

| 术语 | 定义 |
| --- | --- |
| Lifecycle State | Agent 的逻辑存在状态，例如 `Active` 或 `Sleeping` |
| Transition | 由事件触发、经过守卫校验并可审计提交的状态转换 |
| Lease | 有期限的运行或写权限，防止多个实例同时控制同一 Agent |
| Heartbeat | 实例周期性报告的可达或健康信号，不单独证明业务健康 |
| Sleep | Agent 暂停常规执行并释放资源，但保留身份和唤醒条件 |
| Termination | 不可逆地结束 Agent 逻辑生命并撤销运行权限 |

## 状态与可靠性

| 术语 | 定义 |
| --- | --- |
| Event | 已经发生且不可被命令式“撤销”的事实记录 |
| Command | 请求某个主体执行动作的意图，可能被拒绝或过期 |
| Snapshot | 用于恢复 Agent 逻辑连续性的版本化一致状态 |
| Checkpoint | 一个确认可恢复的处理位置，通常引用快照和事件水位 |
| Idempotency Key | 让重复请求获得相同业务效果的唯一键 |
| Compensation | 用新的动作抵消已发生副作用，不等同于数据库回滚 |
| Recovery Point | 已验证可用于恢复的一组状态、事件水位和版本引用 |
| Failure Domain | 故障应被限制在其中的组件、Agent、租户或资源范围 |

## 记忆

| 术语 | 定义 |
| --- | --- |
| Working Memory | 支持当前任务的短期状态和上下文 |
| Episodic Memory | 对经历、过程、结果和评价的记录 |
| Semantic Memory | 从经验或权威来源抽取的事实和规律 |
| Procedural Memory | 已验证的技能、流程和策略 |
| Self Memory | 关于能力、失败模式、限制和成长的长期记录 |
| Provenance | 数据或结论的来源、时间、处理链和责任主体 |
| Retention Policy | 决定数据保留、降权、归档和删除的规则 |

## 协作与治理

| 术语 | 定义 |
| --- | --- |
| Delegation | 在明确目标、权限、预算和责任下把任务交给另一个主体 |
| Relationship | 两个 Agent 或主体之间版本化、可撤销的协作和授权记录 |
| Approval | 绑定具体内容、范围、版本和有效期的授权决定 |
| Policy | Runtime 强制执行的访问、资源、安全和治理规则 |
| Audit Record | 能够重建谁基于什么授权执行何种动作及其结果的证据 |

## 演化

| 术语 | 定义 |
| --- | --- |
| Reflection | Agent 对经验的解释或改进假设，不是已验证事实 |
| Evolution Candidate | 等待实验和验证的长期行为变更候选 |
| Stable Version | 当前被批准用于正常执行的版本 |
| Shadow Run | 使用真实输入但不产生真实外部副作用的候选版本运行 |
| Canary Release | 将候选版本限制在小范围任务或流量中的灰度发布 |
| Rollback | 将行为及相关配置、记忆引用恢复到已验证稳定版本 |

## 规范词

- **必须**：实现不满足即违反核心设计契约。
- **应**：强烈推荐；偏离时需要记录理由和替代保障。
- **可以**：允许的可选实现，不影响核心语义。
- **当前**：只描述仓库或系统中可直接验证的现状。
- **候选**：尚未经过实现和测试证明的提案。
