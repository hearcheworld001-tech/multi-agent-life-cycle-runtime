# 常见问题

## 这是一个已经可以运行的 Agent 框架吗？

不是。当前仓库是架构设计文档和 VitePress 文档站，没有 Runtime 核心代码。路线图中的接口和模块是后续实现需要验证的候选。

## 它与工作流编排框架有什么区别？

工作流编排通常关注一次流程的节点、依赖和结果。生命运行时还必须管理跨任务和跨进程的身份连续性、休眠与唤醒、记忆、恢复、权限、资源和长期演化。未来实现可以使用工作流框架，但工作流框架本身不能替代这些语义。

## “长期存在”是否意味着进程永不停止？

不是。Agent 的逻辑身份可以在进程停止、主机迁移或长期休眠后继续存在。持续性来自事件、快照、版本和恢复协议，而不是单个进程永远在线。

## Agent 和大模型是什么关系？

大模型可以是 Agent 的推理能力之一，但 Agent 还包括身份、目标、状态、记忆、工具、权限和行为闭环。更换模型不应自动创建新的 Agent 身份，但可能形成能力版本变化。

## Engine 会替 Agent 做决定吗？

Engine 负责校验权限、预算、生命周期和安全边界，可以拒绝或暂停动作；目标解释、领域判断和行动意图由 Agent 负责。Engine 的策略约束不等于替 Agent 做价值判断。

## 为什么需要事件日志和快照两套机制？

事件日志解释发生了什么，快照加快恢复。只有快照难以审计原因，只有事件日志则恢复成本过高。快照必须绑定事件水位，二者共同形成恢复点。

## 为什么不直接把所有历史放进向量数据库？

相似度不能解决来源、权限、冲突、过期、敏感度和实际效用。日志和文档需要经过选择与评价，才能成为长期记忆；检索也需要结合权限、可信度和适用范围。

## 自我进化是否意味着 Agent 可以直接修改代码？

不是。反思只产生候选变更。高影响策略、权限、代码和架构变更必须经过隔离实验、回归验证、审批、灰度发布和回滚门禁。当前设计明确反对未经验证的在线自修改。

## 多 Agent 协作为什么不能只用群聊？

聊天记录缺少稳定任务身份、版本、权限、截止时间、幂等、责任和恢复语义。可靠协作需要结构化消息和委托协议；自然语言可以作为负载，但不能代替控制字段。

## 能否选择 LangGraph、Temporal 或其他框架实现？

可以，但应先证明它能承载生命周期、事件、快照、幂等、副作用恢复和人工审批等契约。框架是实现工具，不是设计事实。某些场景可能需要组合工作流引擎、消息系统和自定义控制面。

## 为什么 `Terminated` 不允许恢复？

终止代表身份生命周期和权限已经不可逆结束。允许直接复活会破坏审计、权限撤销和责任边界。如果需要延续使命，应创建新 Agent，并显式记录继承关系。

## 如何判断一条经验值得记住？

看它是否具有未来效用、可靠来源、明确适用范围和足够评价证据。异常结果、新规律、高风险失败、人类显式要求和可泛化技能通常更有价值；可重新计算的低价值日志通常不应进入长期记忆。

## Cloudflare Pages 发布的是 Markdown 吗？

不是。Markdown 是源文件，VitePress 在构建时生成 HTML、CSS 和 JavaScript，Cloudflare Pages 发布生成后的静态站点。浏览器最终读取的是 HTML 页面。
